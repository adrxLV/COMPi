# COMPi public-app UX audit

**Observed 20 October 2026** at [the public deployment](https://adrxlv.github.io/COMPi/), in a Chromium browser at 1280 × 577 and an emulated 390 × 844 mobile viewport.[6] I opened the path and first activity, submitted a wrong answer, used its Next activity control, returned to the path and opened Mistake lab. Findings below describe that deployed snapshot, not a completed redesign or every route. The [learning contract](LEARNING_CONTRACT.md) is the intended behaviour, and [Duolingo principles](DUOLINGO_PRINCIPLES.md) explain the reference without treating Duolingo as a template.

## Executive finding

The public app already offers real syllabus-aligned Python questions, optional hints, original-practice labelling and an accessible separate review route. Its main guided journey still presents seven week-sized nodes and an explanation alongside a question. More consequentially, a wrong guided answer displays **Next activity**, which I used to advance without correcting the answer. The high-value change is not visual imitation: make each small concept unit a recoverable sequence of teaching, retrieval and completion, while preserving first-try XP semantics and prior state. Duolingo's published path rationale emphasises smaller units and interleaved review, but its 2022 design article does not establish what COMPi should copy pixel-for-pixel.[1][2][3]

## Reproducible observations and priorities

| Priority | Evidence from the deployed browser / repository | Learning or UX consequence | Recommendation / acceptance check |
|---|---|---|---|
| **P0 — stop a wrong-answer skip in guided lessons** | In the first Week 1 choice question (`w1-error-categories`), I selected “Syntax error” for a program that runs but gives the wrong result. The feedback said “Not quite. Try again.”, explained that execution succeeded but the result did not match intent, and presented **Try again** **and Next activity**. Pressing **Next activity** loaded `w1-syntax-diagnosis` with 0 XP. `src/App.tsx`'s lesson feedback action also offers next independent of correctness. | The learner can progress despite a known misconception; the instructional sentence is shown, but no corrected retrieval is required. The skipped question remained in Mistake lab, a useful safety net that does not repair the guided flow. | On wrong in a path unit, retain retry and revisit teaching, remove/disable direct advance until a correct response. Record both miss and recovery; subsequent correction permits progress but not first-try XP. Check the wrong → retry → correct → next sequence in browser. The [contract](LEARNING_CONTRACT.md) expressly requires this. |
| **P1 — one learning task per screen** | The first lesson displays a paragraph defining syntax/runtime/semantic errors and a code example directly above the question. Both were visible in the same document view at desktop and emulated mobile. Seven path buttons correspond to weeks, with 5, 5, 5, 8, 7, 7 and 15 activities respectively (52 total in the deployed path). `src/content/index.ts` currently assembles exercises by week. | A week is too broad to provide a clear short-session finish, and concurrent explanation can substitute for recall; Week 7's 15 activities particularly risks a long apparent unit. This is an inference about design risk, not measured drop-off. | Use focused concept units from the existing bank: a brief teaching screen, one question per screen, then a completion screen; label activity position and keep exit/resume. At most one authored instance of each of the 52 IDs, no fabricated questions. A one-question unit is practice, not a mastery certification. |
| **P1 — explain progress at the right granularity** | At a new profile the path says “0 / 52 activities completed”; only node 1 is enabled, nodes 2–7 are disabled; “Continue learning” opens the first activity. At 390 px emulated width the question occupied x=16 to x=374, with document scroll width=390, so no horizontal overflow appeared in this one lesson state. | The next action is obvious, but “Week 7 / 15” is a daunting commitment; the path offers no small-unit completion waypoint in this deployed version. The no-overflow result is narrow evidence, not mobile accessibility certification. | Show current unit, question count, forthcoming unit and completed-unit status without implying that activities answered with help were independent. Preserve earned XP, attempts, drafts and completions across state migration; verify with existing profile/backup fixtures. |
| **P1 — make review forward progress without hiding it** | A wrong attempt put `w1-error-categories` in **Mistake lab**; the separate desktop navigation contains Practice arena, Python traps and Mistake lab. The mobile bottom nav shows Learning, Practice, Playground, Exam and Progress, but not a direct Mistake lab item. | A separate review route exists, yet a novice on mobile may not discover it from the five bottom destinations; the path does not visibly embed review in this tested state. This is a discoverability hypothesis, not a measured user failure. | Surface due retrieval at an appropriate later point on the path and link to targeted practice without blocking unrelated activities. Keep independent practice available. Test a due question after a miss and after a later session; do not present the existing queue as a validated spacing algorithm. Duolingo describes both in-path review and a separate on-demand Practice tab.[2][3][5] |
| **P2 — contextual, honest feedback** | The first incorrect answer provided a relevant conceptual explanation but no demand to apply it before Next. The production UI also has **Show a hint** before submission and labels the course “Original practice … Not an official university assessment.” `docs/DECISIONS.md` says one-time XP comes from first unaided correct answers and is not mastery. | Explanation and optional help are strengths; showing full explanation before recovery can reduce the diagnostic value of the next try if the same choice is repeated. | Keep concise rationale and option to retry, but assess recovery separately from first-try performance. For executable tasks, offer bounded feedback from actual test cases; do not confuse XP, completion and long-term retention. Duolingo's 2026 account emphasises timely, contextual explanations, not automatic mastery.[4] |

## Pedagogical translation, not a clone

Duolingo describes interactive small steps, optional hints and bite-sized explanations, guided smaller units with built-in interleaved practice, and later active recall.[1][2][3] For COMPi, preserve the course-specific Weeks 1–7 scope and the genuine Python grading path. Start a focused unit with its contractually required short teaching screen; ask an answer without the explanation simultaneously in view; recover from a mistake before advancing; revisit a prerequisite after a delay with a different question format if an existing item permits. Keep the open Practice arena and the original exam simulation distinct from the guided path. Do not import mascot art, energy/hearts, a paid feature, generated questions or Duolingo's unobservable personalisation model. The 2026 official Practice-tab post illustrates how free-choice practice can coexist with a path, not that every Duolingo platform shares the same exact controls.[5]

## Scope and validation gaps

- **Observed directly:** fresh path state and seven node lock states; first Week 1 choice, wrong feedback, actual skip to the next question; Mistake lab containing the missed item; one emulated mobile lesson state without horizontal overflow. Browser reads were DOM text/state checks; an attempted screenshot timed out, so this is not a pixel-level visual review. The incorrect attempt was made in the audit browser profile, not a test of migration.
- **Not observed:** completion after all questions, persistence across reload/import, any Week 2–7 question journey, Python-worker grading, keyboard or screen-reader behaviour, actual delayed-review scheduling, learning outcomes, offline cache readiness, reduced-motion behaviour and real-device ergonomics. Source inspection and the contract establish intended architecture, not deployed runtime success.
- **No iOS Safari test:** the 390 × 844 mode was Chromium device-metric emulation, not WebKit or a physical iPhone. It cannot validate Safari viewport/keyboard behaviour, touch interactions, IndexedDB eviction, service-worker installation or Pyodide memory constraints. Test those separately before release claims.
- **Temporal limit:** GitHub Pages may deploy a different build after this audit; this is a 20 October 2026 snapshot. Duolingo's 2022 path article is a historical rationale; the 2026 feedback and practice announcements are product descriptions, not efficacy results for Python learning.[2][4][5]
