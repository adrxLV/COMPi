# Learning-path redesign contract

The app retains its existing React/Vite shell, 52 exercise IDs, grading path and Python worker. A `LearningUnit` in `src/contracts.ts` is a focused concept: one teaching screen, one question screen per `exerciseIds` entry, then a completion screen. No duplicated question text or fabricated score. `TeachingStep` is an optional, explicitly Python-verified static visual teaching example, not an execution trace.

`src/content/learning.ts` owns ordered `learningUnits` and mapping to existing exercise IDs; source scope remains Weeks 1-7. Every exercise is assigned to exactly one unit, ordered with introductory reasoning before complex work where the bank permits it. A unit with only one suitable question must not pretend to prove mastery. Week 7 aliases/copies must be marked enrichment if the source does not establish assessment.

`LearnerState` v2 adds `journey` with an optional active `{unitId,screenIndex,startedAt,missed,recovered,revealed}` and `completedUnits`. Existing v1 profiles/backups migrate by retaining all earned XP, attempts, completed exercise IDs, drafts and exam data. Already-started v2 profiles also migrate their active screen indices into the review phase. A migrated unit is complete if all its exercise IDs were previously completed; never wipe old state.

`LessonFlow` presents one question at a time. Contextual teaching review returns to the same question without changing its persisted position. `Answer` is imported from `src/assessment/grade.ts`. Index 0 is teaching, 1..N are first-pass questions, N+1..N+M are review of the M missed questions, and N+M+1 is completion. `ExerciseInput` owns presentation, not grading or storage; `App.tsx` handles submission and navigation, while `src/storage/journey.ts` defines the durable flow. A wrong first-pass answer records an attempt and permits continuation, then reappears at the end for a retry or `Show answer`. A revealed answer is tracked separately and does not count as correct or award XP. Completion requires all original questions to be attempted and every miss to be recovered or revealed. First-try XP is computed from durable attempts, including after reload. Textual error classes accept common equivalent names; multipart repairs may declare curated valid alternatives. Exact-output questions remain exact. Other modes retain their existing grading contracts.

The application remains static and local-first: no backend, account, remote grading service or mandatory AI runtime. Publishing requires an explicit GitHub push and separate verification of the Pages workflow and live URL.
