# Python runtime

`runPython(request)` resolves to a `RuntimeResponse` using the caller's `id`; `cancelPython()` terminates the worker, resolves active and queued requests as cancelled, and creates a clean interpreter on the next run. The active request has a 20-second wall-clock deadline, including first-time Pyodide startup. On timeout its worker is terminated, its response has `timedOut: true`, and queued work runs in a new worker. Worker messages are correlated by ID. Keep request IDs unique among outstanding requests.

Pyodide's JS loader is bundled into the module worker; its WASM, Python standard library, and lockfile are fetched from `${import.meta.env.BASE_URL}pyodide/` (copy the matching `pyodide` npm package assets to `public/pyodide/`). Python executes in the browser, not on a backend. Output streams are capped at 100,000 characters apiece. `input(prompt)` writes the prompt to stdout and consumes `inputs` in order; exhaustion raises `EOFError`. `grade` runs each case in a fresh Python globals dictionary, using the case's `input`, and compares stdout with `expectedOutput` ignoring only trailing newline characters. Individual failures appear in `cases`.

Trace captures each Python `line` event for code compiled as `<user>`, plus the top-level return (final state and output). A frame is the state *before* executing its indicated line, except the final return frame. Python functions defined by the snippet are included; native extension/C calls, mutations between line events, and imported module internals are not. `bindings` list visible user names, sorted alphabetically; `objectId` is a per-execution identity (aliases share it), while `repr` is a truncated snapshot of the value at that point. At most 50 bindings per frame, repr length 160, and 2,000 trace steps are retained; exceeding `maxSteps` raises `RuntimeError`. Separate requests/cases get fresh globals but share imported module state until worker termination. This is not a security sandbox for hostile code.
